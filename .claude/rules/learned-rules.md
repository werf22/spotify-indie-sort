- [2026-07-04] FastAPI: commit in a yield-dependency teardown runs AFTER the response is sent — every mutating endpoint must call session.commit() explicitly before returning — client refetch races the commit and a failed commit would be silent after a 2xx; found live by Playwright E2E in optistock ("Obidve sprav" — owner 4.7.).
- [2026-07-04] Tests on a different DB dialect than production (SQLite vs MSSQL) cannot catch dialect bugs — before claiming a data path works, smoke it once against the TARGET dialect; ban `.is_(True/False)` (renders IS 1 = MSSQL syntax error) and offset() without order_by() — golden dry-run caught `.is_(True)` in the core feed that all 130 SQLite tests missed. Sharpened 2026-07-19 (owner approved): DB migrations additionally need a FRESH-INSTALL smoke on the target dialect family (MySQL aj MariaDB, napr. lokálny e2e docker stack) — named inline column CHECK a `DROP CHECK` sú MySQL-only (MariaDB 1064/1826), a pád migrácie uprostred na MySQL (DDL auto-commit, bez txn) necháva čiastočnú schému, kde každý retry umrie na "table already exists", pokiaľ CREATE nie je idempotentný. Sharpened 2026-08-10 (owner approved): the same trap applies BEYOND databases to any platform-specific tooling — a shell/OS test on the dev machine can pass VACUOUSLY because the tool simply isn't there; verify on the target OS before claiming green (najlepsiaponuka 10.8.: a `flock` concurrency guard "passed" on macOS only because macOS has no `flock`, so the lock was silently skipped — on the Linux server the same test correctly rejected the second run).
- [2026-07-20] never drive billed remote compute (GPU pods etc.) through a live/foreground SSH session — run it detached on the remote (nohup + done/fail markers), pull results incrementally, and add self-stop + server-side time caps — a local network drop must never kill paid work or leave it billing idle; learned when 3 of 17 RunPod shards lost 2-5h each (~19% of spend) to SSH drops (spotify-indie-sort D-025). SHARPENED 2026-08-07 (owner: "Všetko nech je vždy resumable"): applies to ALL long-running work, local included — any process outliving the current turn (daily runs, ingests, computations) runs DETACHED (screen -dmS / nohup / service), never in a session-bound shell, and must be resumable after interruption (persisted state + recovery path); live proof 4.8.: denný beh started in an AI-session shell would have orphaned on session close — killed early and relaunched in detached screen. SHARPENED 2026-08-11 (owner: "Pravidlo uloz"): the local network drop can be SELF-INFLICTED — never saturate the uplink of the machine controlling paid remote compute (large git push, bulk upload, big sync) while paid pods run; the control plane shares that link with the work's own transfers, so DNS/API calls start failing and pods are orphaned mid-flight. Proof spotify-indie-sort 11.8.: a 266 MB first push to GitHub broke api.runpod.io lookups, killed every shard runner, and left two pods billing unmanaged (D-049). Corollary: the ONLY guard that survives a dead link is the provider-side stop/terminate deadline — keep it sized to real measured runtime, not a stale estimate.
- [2026-08-10] Before SCHEDULING any protective job (backup, restore-test, log/data cleanup), size its resource footprint against MEASURED free resources — peak usage, not steady state — and make its own guard unable to starve it; otherwise the job causes exactly the outage it exists to prevent — najlepsiaponuka 10.8.: retention of 7 daily dumps (1.2 GB each) against 8.8 GB free would have let the MIN_FREE_GB guard silently refuse every backup after a few days (exit 2 into a log nobody reads = false confidence), and the monthly restore-test would have built a full 7.4 GB copy of the DB with 6.4 GB free, filling the disk and taking the site down.

- [2026-08-12] A safety guard that has never actually fired is NOT a guard — before trusting any protective mechanism, prove it has triggered at least once against the real condition (or a test reproducing it). Two guards were inert for weeks while looking healthy: a pod self-stop gated on an env var the platform only injects into PID 1 (never into ssh sessions), and a runner-liveness check using `pgrep -f <script>` that matched ANY process merely mentioning the name — so an abandoned paid resource looked "managed" and was spared. Both provided confidence and zero protection (spotify-indie-sort D-048/D-050).
- [2026-08-12] A watchdog must NOT share a process, host lifecycle, or failure mode with what it guards — run it as a separately supervised process. Proof: one saturated uplink killed the shard runner AND the orchestrator together, so both the per-task guard and the sweeper died at the same instant and paid pods billed unwatched (spotify-indie-sort D-049/D-050).
- [2026-08-12] Before optimizing anything, MEASURE where the time/cost actually goes and split it into fixed vs variable — do not tune what you have not profiled. Three rounds of CPU/thread tuning (3-4x more CPU) bought 8% end-to-end because 68% of every unit's cost was fixed setup overhead nobody had measured; the one change that attacked the fixed part beat all of them (spotify-indie-sort D-045).
- [2026-08-12] Never let INFRASTRUCTURE failures count toward permanent-failure thresholds (quarantine, dead-letter, max-attempts) — classify the error by cause before counting it. A single host with a wedged GPU wrote 375 identical CUDA errors; under a naive 3-strike rule those 375 perfectly good items would have been permanently retired as unprocessable, and the batch would have reported itself complete without them — silent data loss wearing a clean finish (spotify-indie-sort D-040).
- [2026-08-12] Every state value a record can hold must be reachable by SOME query, and a worker reporting "zero work" must prove it is FINISHED, not STUCK — a status no selector looks at is a silent leak with no error attached. 603 rows sat in 'processing' for three weeks, invisible to a selector that only considered missing-or-failed rows, while the lane logged "ok=0, failed=0" every cycle, indistinguishable from being done (spotify-indie-sort D-043).
- [2026-08-12] When introducing a new generated filename or artifact type, check EVERY cleanup/retention job that deletes by name — allowlist-based pruning silently deletes anything not on its list. A prune job with a keep-list deleted freshly written .gz archives minutes after creation because the new name was never added to it (spotify-indie-sort D-041 era).
- [2026-08-12] Read the ENFORCED limit, never the advertised one: cgroup quota over `nproc`, and container env from `/proc/1/environ` or the platform's env file rather than the ssh session. Same-priced cloud hosts enforced anywhere from 6 to 27 CPUs while `nproc` reported the 128-core host, and a required variable existed only in PID 1 — so both a hardcoded thread count and an env-var guard were wrong in opposite directions (spotify-indie-sort D-039/D-044/D-048).
- [2026-08-12] Compare measurements on the SAME unit under the SAME conditions — a cross-run A/B under differing load is noise, and reading it either way is self-deception. Two runs gave 11.9 vs 11.4 min and looked like "no improvement"; measuring both phases inside ONE run proved a real 4.8 min saving that the cross-run comparison had hidden behind differing network contention (spotify-indie-sort D-045).
- [2026-08-12] Before auto-accepting fuzzy matches, check what the LOOSENED rule actually matches — normalization that raises recall destroys precision when the discriminating detail lives in exactly what you strip. Stripping parenthetical suffixes to widen title matching would have matched 1,083 of 1,084 items whose titles differed precisely there (remix vs original, feat. vs not), writing the original's tempo onto remixes across a DJ library (spotify-indie-sort D-046).
- [2026-08-12] SQLite with several writers: use BEGIN IMMEDIATE for any transaction that reads and then writes — a deferred transaction upgrading its lock gets SQLITE_BUSY_SNAPSHOT returned IMMEDIATELY, and `busy_timeout` does not retry that class, so batches die after one row while looking like ordinary lock contention (spotify-indie-sort D-043).
